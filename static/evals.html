Question-by-question results

Evaluation methodology
  • The questions. 50 fixed questions about decisions, votes, dissents, topics, year comparisons, follow-ups, reworded versions of the same question, and meetings whose minutes are not public yet. Code generates them (tests/make_key.py), so every model gets the identical set.
  • Who decides the right answer. No person and no AI. The answer key comes from the Fed's minutes: each meeting's decision, target range and vote are read out of the minutes text by code, and those readings were checked against the actual change in the federal funds rate for all 150 meetings (tests/testDecisions.m).
  • Who grades the answers. Code, not a person or an AI judge. Each answer is checked with fixed text patterns: the right direction (raised, cut or held), the right rate range, the right dissenters' names, or "not public yet" wording for unreleased meetings. A question counts as correct only if every check matches.
  • What the grader cannot see. Because it reads text, an unusual but correct phrasing can be marked wrong. Topic and comparison questions only check for the topic words or both years, so a high score there is lenient. The 4 "why" questions have no key and are not scored; they only feed the invented-reason flag.
  • Baseline. The same Ollama model and context size, given only the question and the date: no tools, minutes, data, guardrail or citation check. "Our agent" is everything we add around the model: the lookups, the point-in-time guardrail and the checks.
  • Limits. One run per model per question, on one 8 GB Apple M1, so run-to-run variation is not measured. Every score is out of 46, so differences of a few points are not meaningful.
